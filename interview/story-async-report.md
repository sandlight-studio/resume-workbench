# 异步报表中心（虚构示例）

## 30 秒版本

> 原来的报表在 HTTP 请求里一次查完并生成文件，数据变大后容易超时和占满内存。张三把它
> 拆成持久任务：接口只创建任务，后台按游标分页读取并流式写文件，完成后上传对象存储。
> 同时限制全局和租户并发，记录失败批次，支持从安全检查点继续。

## 状态模型

`PENDING → RUNNING → SUCCEEDED | FAILED | CANCELED`

- 创建任务时保存筛选条件快照和请求人。
- 工作者获取带过期时间的租约，租约续期失败就停止继续写。
- 每批完成后记录游标和行数，文件写入临时对象。
- 全部成功后原子发布最终下载对象，再更新任务终态。

## 关键取舍

**为什么不用 offset 分页？** 数据在导出期间仍可能变化，较深 offset 成本也会上升。示例按
稳定排序键做游标分页，并在任务开始时保存查询边界。

**为什么不把整个文件放内存？** 内存上界会随数据量和图片体积增长。流式写出让占用主要由
批大小决定。

**为什么需要两层限流？** 全局上限保护数据库和工作节点；租户上限避免单个用户占满全部槽位。

## 失败处理

- 查询暂时失败：保留检查点并有限重试。
- 单行数据非法：记录失败明细，按产品规则决定跳过还是终止。
- 上传失败：保留临时对象，重试上传而不是重新查询全部数据。
- 工作节点退出：租约过期后由其他节点从检查点继续。

## 验收场景

- 相同任务消息被重复消费时只有一个工作者持有有效租约。
- 取消中的任务不再读取新批次。
- 下载地址过期后不能访问，但任务记录仍可审计。
- 一次大型报表不能阻塞普通在线查询。
