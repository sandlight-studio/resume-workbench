# 线上故障排查（虚构示例）

## 通用开场

先确认影响面和时间线，再止损；保留证据后定位，不在证据不足时同时修改多个参数。

1. **影响面：**哪些接口、租户、版本和节点异常？
2. **时间线：**告警、发布、配置变更和流量变化谁先发生？
3. **止损：**限流、降级、回滚或隔离故障节点。
4. **证据：**指标、日志、追踪、线程转储、数据库活动会话。
5. **验证：**用最小改动验证假设，观察相同指标是否恢复。
6. **复盘：**补测试、告警、容量边界和运行手册。

## 示例：连接池等待升高

**现象：**协作任务平台接口延迟上升，应用线程大量等待数据库连接。

**排查路径：**

- 对齐异常开始时间与发布、批处理任务和流量变化。
- 查看连接池活跃数、等待数、获取耗时与超时次数。
- 查看数据库慢查询、锁等待、活动事务和执行计划。
- 在线程转储中确认线程是在等待连接，还是持有连接等待下游。

**虚构根因：**报表任务复用了在线连接池，多个工作者执行低选择性查询，连接长时间不归还。

**处理：**暂停新报表、降低工作者并发恢复服务；随后拆分工作负载、增加查询边界和索引，
并为连接等待与报表队列设置告警。

**不要这样讲：**“把连接池从 20 调到 100 就好了。”如果数据库承载能力不变，这通常只是
把排队位置从应用移到数据库。

## 症状速查

| 症状 | 优先证据 |
|---|---|
| CPU 高 | 火焰图、线程 CPU、GC、热点请求 |
| 内存持续增长 | 堆使用趋势、GC 后基线、堆转储、对象保留链 |
| 消息积压 | 生产/消费速率、单条耗时、失败重试、分区热点 |
| 接口慢 | 分段耗时、下游依赖、连接池、慢 SQL、锁等待 |
| 错误率突增 | 发布差异、错误类型、受影响请求特征、依赖状态 |
